  • Proxmox VE auf HP EliteDesk 800 G3 · 16 GB RAM · 1 TB NVMe, 512 GB SSD, 2 TB HDD

  • Zugriff von außen über Tailscale und Cloudflare Tunnel mit Zero-Trust-Access

  • Umzug aller Container und Medien von SATA-SSD auf NVMe per pct move-volume

06 / Engineering Notes

Konkrete Probleme, Entscheidungen und Ergebnisse aus meinen Projekten — kurz notiert.

Cloudflare · Zero Trust10/2026

Zero Trust statt offener Dashboards

Problem Ein internes Homelab-Dashboard war über eine Subdomain öffentlich erreichbar.

Nur noch mit Login erreichbar
  • Cloudflare Tunnel als einziger Eingang — kein Port-Forwarding am Router
  • Access-Policy: nur meine E-Mail, Login per One-Time-PIN
  • Private Dienste ausschließlich über Tailscale
  • Lehre: regelmäßig prüfen, was DNS und Tunnel tatsächlich veröffentlichen
Ausführlich lesen →
SEO · Build · i18n10/2026

Mehrsprachige statische Seiten ohne Framework

Problem Übersetzungen wurden nur per JavaScript getauscht — Google indexierte ausschließlich Deutsch.

4 indexierbare Sprachversionen
  • Node-Skript ohne Abhängigkeiten rendert /en/, /ru/, /ua/ aus einer Quelle vor
  • hreflang, eigene canonical-URLs und Sitemap mit Alternates
  • CI-Check schlägt fehl, wenn generierte Seiten veraltet sind
  • Weiterleitung nur bei expliziter Sprachwahl — Crawler sehen immer Deutsch

Proxmox · LXC · Storage09/2026

Proxmox-Umzug auf NVMe

Problem Alle Container lagen auf einer SATA-SSD, die Medien auf einer dauerhaft laufenden USB-HDD.

HDD nur noch für Backups
  • Root-Disks aller 4 LXC-Container per pct move-volume auf einen NVMe-Thin-Pool verschoben
  • Medienbibliothek auf eigenes LVM-Volume, Bind-Mounts der Container umgestellt
  • SMART-Check: die „neue“ NVMe war gebraucht — 33 TB geschrieben, aber gesund
  • HDD wird nur noch vom täglichen vzdump-Backup genutzt (7 / 4 / 3)

Cloudflare Workers · Edge04/2025

Cloudflare Worker als AI-Proxy

Problem Der AI-Chat auf dieser Seite braucht einen API-Key, der nicht im Browser landen darf.

API-Key nie im Browser
  • Das Chat-Widget spricht mit einem Worker, nur der Worker kennt den Groq-Key
  • Kein eigener Server, kein Cold Start, globales Edge-Netz
  • Zentrale Stelle für CORS und Rate-Limiting
  • Live testbar: „Frag AI über Serge“ unten rechts
FastAPI · Telegram · systemd03/2025

FastAPI-Microservice statt No-Code

Problem Das Kontaktformular hing an n8n und Formspree — fremde Dienste für eigene Daten.

Keine Drittanbieter für Formulare
  • Eigener FastAPI-Endpoint validiert Eingaben
  • Weiterleitung über die Telegram Bot API
  • Läuft als systemd-Service mit Auto-Restart auf eigenem VPS
  • Lehre: kleine eigene Services sind oft einfacher als No-Code-Ketten
nginx · systemd · VPS03/2025

Von PaaS auf eigenen VPS

Problem Projekte waren über Render, Netlify und Supabase verteilt — mit Limits und Cold Starts.

Mehrere Projekte auf einem VPS
  • nginx als Reverse Proxy, SSL-Terminierung über Cloudflare
  • Jeder Dienst als eigene systemd-Unit mit Auto-Restart
  • PostgreSQL und automatische Backups selbst verwaltet
  • Lehre: mehr Kontrolle heißt auch mehr Verantwortung für Monitoring

Groq · OpenAI · LLM11/2024

Groq vs. OpenAI: Geschwindigkeit vs. Qualität

Problem Echtzeit-Chat fühlte sich mit großen Modellen zu langsam an.

~10× schnellere Antworten
